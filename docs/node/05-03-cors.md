# Module 5.3: CORS — Cross-Origin Resource Sharing 🌐

> 💡 **เป้าหมาย:** เข้าใจกลไก CORS ว่าทำงานอย่างไรและตั้งค่าให้ถูกต้อง เพื่อให้ Frontend ของระบบ WSA2026 สามารถเรียก API ได้อย่างปลอดภัยโดยไม่โดนบล็อก

---

เวลาเขียน Frontend (React/Vue) แยก Domain กับ Backend (Node.js) แล้วเรียก API แล้ว Error แบบนี้... คุณเคอเจอไหม? 😤

```
Access to XMLHttpRequest at 'http://localhost:3000/api/submissions'
from origin 'http://localhost:5173' has been blocked by CORS policy:
No 'Access-Control-Allow-Origin' header is present on the target resource.
```

ยินดีต้อนรับสู่นรก CORS! 🔥 — บทนี้จะอธิบายให้เข้าใจจริงๆ ว่า CORS คืออะไร ทำงานยังไง และแก้ยังไงอย่างถูกต้อง


## 📖 ทฤษฎีและแนวคิด (Theory & Concepts)

### 1. CORS คืออะไร? (The Real Story)

#### 1.1 Same-Origin Policy (ต้นเหตุของทุกอย่าง)

ก่อนจะเข้าใจ CORS ต้องเข้าใจ **Same-Origin Policy** ก่อน

Browser มีกฎเหล็กข้อหนึ่งชื่อว่า **Same-Origin Policy (SOP)** บังคับว่า:

> **"JavaScript จากหน้าเว็บ A จะยิง HTTP Request ไปหา Server B ไม่ได้ (ถ้าคนละ Origin)"**

**Origin** คืออะไร? ประกอบด้วย 3 อย่าง:

| ส่วนประกอบ | ตัวอย่าง |
|:---|:---|
| **Protocol** | `http://` หรือ `https://` |
| **Domain** | `localhost` หรือ `api.wsa2026.com` |
| **Port** | `:3000` หรือ `:5173` |

**ถ้าทั้งสามอย่างเหมือนกัน = Same-Origin ✅**
**ถ้าต่างกันแม้แต่อย่างเดียว = Cross-Origin ❌**

```
http://localhost:5173  ยิงไปที่  http://localhost:3000
                                                ↑ Port ต่างกัน! = Cross-Origin
```

#### 1.2 ทำไม Browser ถึงบล็อก?

เพราะ Browser ป้องกัน **CSRF Attack (Cross-Site Request Forgery)** — สมมติว่าคุณเปิดเว็บอันตราย และ JavaScript ในเว็บนั้นแอบยิง Request ไปลบ submission งาน WorldSkills ของคุณ Browser จะบล็อกมันไว้!

#### 1.3 CORS = การขอ "อนุญาต" จาก Server

**CORS (Cross-Origin Resource Sharing)** คือกลไกที่ Server บอก Browser ว่า:

> **"โอเค ฉันอนุญาตให้ Origin นี้เรียกหาฉันได้นะ"**

ผ่านทาง HTTP Response Header:

```
Access-Control-Allow-Origin: http://localhost:5173
```

เมื่อ Browser เห็น Header นี้ มันจะปล่อยให้ JavaScript อ่าน Response ได้ ✅

### 2. CORS Flow ทำงานยังไง?

```
╔══════════════════════════════════════════════════════════════════╗
║               WSA2026 CORS FLOW DIAGRAM                          ║
╠══════════════════════════════════════════════════════════════════╣
║                                                                  ║
║  CASE 1: Simple Request (GET, POST ธรรมดา)                       ║
║  ─────────────────────────────────────────                       ║
║  Frontend (localhost:5173)          API (localhost:3000)         ║
║        │                                    │                    ║
║        │── GET /api/submissions ──────────► │                    ║
║        │   Origin: http://localhost:5173    │                    ║
║        │                                    │                    ║
║        │◄── 200 OK ─────────────────────── │                    ║
║        │    Access-Control-Allow-Origin:    │                    ║
║        │    http://localhost:5173           │                    ║
║        │                                    │                    ║
║     ✅ JavaScript อ่าน Response ได้                              ║
║                                                                  ║
║  CASE 2: Preflight Request (DELETE, Authorization header)        ║
║  ──────────────────────────────────────────────────────         ║
║  Frontend (localhost:5173)          API (localhost:3000)         ║
║        │                                    │                    ║
║        │── OPTIONS /api/submissions ──────► │  ← Preflight!     ║
║        │   Origin: http://localhost:5173    │                    ║
║        │   Access-Control-Request-Method:   │                    ║
║        │   DELETE                           │                    ║
║        │   Access-Control-Request-Headers:  │                    ║
║        │   Authorization                    │                    ║
║        │                                    │                    ║
║        │◄── 204 No Content ─────────────── │                    ║
║        │    Access-Control-Allow-Origin:    │                    ║
║        │    http://localhost:5173           │                    ║
║        │    Access-Control-Allow-Methods:   │                    ║
║        │    GET,POST,DELETE,PATCH           │                    ║
║        │    Access-Control-Allow-Headers:   │                    ║
║        │    Authorization,Content-Type      │                    ║
║        │                                    │                    ║
║        │── DELETE /api/submissions/42 ────► │  ← Actual Request ║
║        │   Authorization: Bearer <token>    │                    ║
║        │                                    │                    ║
║        │◄── 200 OK ─────────────────────── │                    ║
║     ✅ สำเร็จ!                                                   ║
╚══════════════════════════════════════════════════════════════════╝
```

**เงื่อนไขที่จะ Trigger Preflight:**
- Method เป็น `PUT`, `DELETE`, `PATCH`
- Header มี `Authorization`, `Content-Type: application/json`

**ถ้า Server ไม่ตอบ Preflight = Request จริงจะไม่ถูกส่ง!**

### แบบที่ 2: ระบุ Origin ที่อนุญาต — WSA2026 Setup (แนะนำ ✅)

::: code-group

```js [app.js]
require('dotenv').config();
const express = require('express');
const cors = require('cors');

const app = express();

const corsOptions = {
    // WSA2026: อนุญาตเฉพาะ Frontend ของระบบ Competition
    origin: process.env.CLIENT_URL || 'http://localhost:5173',
    methods: ['GET', 'POST', 'PUT', 'DELETE', 'PATCH'],
    // อนุญาต Authorization header สำหรับ JWT Token
    allowedHeaders: ['Content-Type', 'Authorization'],
    credentials: true  // อนุญาต Cookies / Authorization headers
};

app.use(cors(corsOptions));
app.use(express.json());

app.listen(process.env.PORT || 3000);
```

```.env [.env]
PORT=3000
# URL ของ Frontend WSA2026 Competition System
CLIENT_URL=http://localhost:5173
```

### แบบที่ 3: หลาย Origin (Dev + Production) — WSA2026 Multi-Environment

::: code-group

```js [config/corsConfig.js]
require('dotenv').config();

// WSA2026: รองรับทั้ง local dev และ production server
const allowedOrigins = [
    process.env.CLIENT_URL,                    // จาก .env (Competition frontend)
    'http://localhost:5173',                   // Vite Dev
    'https://wsa2026-submission.example.com',  // Production frontend
].filter(Boolean); // กรอง undefined ออก

const corsOptions = {
    origin: (origin, callback) => {
        // อนุญาต Postman / curl ด้วย (origin จะเป็น undefined)
        if (!origin || allowedOrigins.includes(origin)) {
            callback(null, true);
        } else {
            callback(new Error(`CORS blocked: Origin ${origin} not allowed`));
        }
    },
    methods: ['GET', 'POST', 'PUT', 'DELETE', 'PATCH'],
    // Authorization header จำเป็นสำหรับ JWT ใน WSA2026
    allowedHeaders: ['Content-Type', 'Authorization'],
    credentials: true,
    maxAge: 86400  // Cache Preflight 24 ชั่วโมง
};

module.exports = corsOptions;
```

```js [app.js]
require('dotenv').config();
const express = require('express');
const cors = require('cors');
const corsOptions = require('./config/corsConfig');

const app = express();

// 1. CORS ต้องมาก่อนสุด (ก่อน Routes ทุกตัว!)
app.use(cors(corsOptions));

// 2. Body Parser
app.use(express.json());

// 3. Routes — WSA2026 API Endpoints
app.use('/api/submissions', require('./routes/submissionRoutes'));
app.use('/api/tasks', require('./routes/taskRoutes'));
app.use('/api/users', require('./routes/userRoutes'));

// 4. Error Handler (สุดท้ายเสมอ)
app.use(require('./middleware/errorHandler'));

app.listen(process.env.PORT || 3000, () => {
    console.log('WSA2026 API running on port', process.env.PORT || 3000);
});
```

```.env [.env]
PORT=3000
CLIENT_URL=http://localhost:5173
# Production: CLIENT_URL=https://wsa2026-submission.example.com
```

### แบบที่ 4: CORS เฉพาะบาง Route (Public vs Private)

::: code-group

```js [app.js]
require('dotenv').config();
const express = require('express');
const cors = require('cors');

const app = express();

// WSA2026: Public API ดูข้อมูล tasks ได้ทุกคน
const publicCors = cors({ origin: '*' });

// WSA2026: Private API เฉพาะ Frontend Competition เท่านั้น
const privateCors = cors({
    origin: process.env.CLIENT_URL || 'http://localhost:5173',
    allowedHeaders: ['Content-Type', 'Authorization'],
    credentials: true
});

// ดู tasks ได้แบบ Public (ไม่ต้อง Login)
app.get('/api/public/tasks', publicCors, (req, res) => {
    res.json({ tasks: [] });
});

// ส่ง submission ต้อง Private (ต้องมี Authorization header)
app.post('/api/submissions', privateCors, (req, res) => {
    res.json({ message: 'Submission received' });
});
```

:::

### CORS Options Reference ครบถ้วน

```javascript
app.use(cors({
    // ✅ Origin ที่อนุญาต (WSA2026 Competition Frontend)
    origin: process.env.CLIENT_URL || 'http://localhost:5173',

    // ✅ HTTP Methods ที่อนุญาต
    methods: ['GET', 'POST', 'PUT', 'DELETE', 'PATCH', 'OPTIONS'],

    // ✅ Headers ที่อนุญาตให้ Client ส่งมา
    //    Authorization: ใช้กับ JWT Token ใน WSA2026
    allowedHeaders: ['Content-Type', 'Authorization', 'X-Requested-With'],

    // ✅ Headers ที่ Browser จะเห็นในฝั่ง Client
    exposedHeaders: ['X-Total-Count', 'X-Page-Number'],

    // ✅ อนุญาต Cookies และ Authorization header
    credentials: true,

    // ✅ Cache Preflight Response นานแค่ไหน (วินาที)
    maxAge: 86400,  // 24 ชั่วโมง
}));
```

### `credentials: true` ต้องระวัง!

ถ้าใช้ `credentials: true` จะต้องระบุ `origin` ชัดเจน **ห้าม** ใช้ `origin: '*'` เด็ดขาด:

```javascript
// ❌ Error! WSA2026 API จะพัง
app.use(cors({ origin: '*', credentials: true }));

// ✅ ถูกต้อง — ระบุ CLIENT_URL ชัดเจน
app.use(cors({
    origin: process.env.CLIENT_URL || 'http://localhost:5173',
    credentials: true
}));
```

## 🐛 Debug CORS ที่พบบ่อย

### ปัญหาที่ 1: `Access-Control-Allow-Origin` ไม่มี

```
Error: No 'Access-Control-Allow-Origin' header is present
```

**สาเหตุ:** ไม่ได้ใส่ `app.use(cors())` หรือวาง `cors()` ไว้หลัง Routes

**แก้:** ตรวจสอบว่า `app.use(cors(...))` อยู่ก่อน Route ทุกตัว

---

### ปัญหาที่ 2: Preflight ไม่ผ่าน (405 Method Not Allowed)

```
Method Not Allowed — OPTIONS /api/submissions
```

**สาเหตุ:** Server ไม่รับ OPTIONS method

**แก้:** `cors()` จัดการ OPTIONS ให้อัตโนมัติ แต่ต้องวางก่อน Routes:

```javascript
// ✅ cors() จะ handle OPTIONS request อัตโนมัติ
app.use(cors(corsOptions));
app.use('/api', router);
```

---

### ปัญหาที่ 3: `credentials` ไม่ทำงาน

```
Error: The value of 'Access-Control-Allow-Origin' header in the response
must not be the wildcard '*' when the request's credentials mode is 'include'.
```

**แก้:**

```javascript
// Frontend (Axios) — WSA2026 API Call พร้อม JWT
axios.get('/api/submissions', {
    withCredentials: true,
    headers: { Authorization: `Bearer ${token}` }
});

// Backend — ต้องระบุ origin ชัดเจน
app.use(cors({
    origin: process.env.CLIENT_URL || 'http://localhost:5173',
    credentials: true
}));
```

---

### ปัญหาที่ 4: Origin ไม่ตรงเป๊ะ (Trailing Slash)

```javascript
// ❌ มี trailing slash — CORS จะ block!
origin: 'http://localhost:5173/'

// ✅ ไม่มี trailing slash
origin: 'http://localhost:5173'
```

## 🧪 ทดสอบ CORS

### ทดสอบด้วย Curl

```bash
# Simple Request — ทดสอบ GET /api/tasks
curl -H "Origin: http://localhost:5173" \
     -v http://localhost:3000/api/tasks

# Preflight Request — ทดสอบ DELETE พร้อม Authorization header
curl -X OPTIONS \
     -H "Origin: http://localhost:5173" \
     -H "Access-Control-Request-Method: DELETE" \
     -H "Access-Control-Request-Headers: Authorization" \
     -v http://localhost:3000/api/submissions/1
```

ดู Response Header ว่ามี `Access-Control-Allow-Origin` ไหม

### ทดสอบด้วย Browser DevTools

3. ดู Request Headers → มี `Origin` ไหม?

- **โจทย์:** ตั้งค่า CORS สำหรับ WSA2026 API ให้รองรับสถานการณ์ต่อไปนี้:

  **Requirements:**
  1. อ่าน `CLIENT_URL` จาก `.env`
  2. ใน Development: อนุญาต `http://localhost:5173` และ `http://localhost:4173` (Vite preview)
  3. ใน Production: อนุญาต URL จาก `.env` เท่านั้น
  4. รองรับ `Authorization` Header สำหรับ JWT Token
  5. รองรับทุก HTTP Methods (GET, POST, PUT, DELETE, PATCH)

::: details 💡 คำใบ้ (Hint)

- ใช้ `process.env.NODE_ENV` เพื่อตรวจว่าอยู่ใน development หรือ production
- ใช้ `origin` แบบ function `(origin, callback) => { ... }` เพื่อตรวจแบบ dynamic
- อย่าลืม `.filter(Boolean)` เมื่อ build array of origins เพื่อกัน `undefined`
- `credentials: true` จำเป็นเพราะ Frontend ต้องส่ง `Authorization: Bearer <token>`

:::

## 🔥 Challenge (โจทย์ท้าทาย!)

- **โจทย์:** สร้างระบบ CORS แบบ "Role-based Origin Control" สำหรับ WSA2026 โดย:

  1. Route `/api/public/results` — เปิดให้ทุก Origin เข้าได้ (ประกาศผลสาธารณะ)
  2. Route `/api/submissions` — เฉพาะ `CLIENT_URL` จาก `.env`
  3. Route `/api/admin/*` — เฉพาะ `ADMIN_CLIENT_URL` จาก `.env`

  **เงื่อนไขพิเศษ:** ถ้า `ADMIN_CLIENT_URL` ไม่มีใน `.env` ให้ Block ทุก Origin (403) ไม่ใช่เปิดให้ทุกคน

  **เป้าหมาย:** แสดงให้เห็นว่า CORS สามารถทำงานต่างกันตาม Route ได้ และมีการป้องกัน fallback ที่ปลอดภัย

## 🗣️ ทบทวน (Review)

::: details ❓ คำถามทบทวนความเข้าใจ

**คำถาม 1:** Preflight Request คืออะไร และเกิดขึ้นเมื่อไหร่?

**แนวคำตอบ:** Preflight Request คือ HTTP Request แบบ `OPTIONS` ที่ Browser ส่งไปถาม Server ก่อนโดยอัตโนมัติว่า "ฉันขอส่ง Request แบบนี้ได้ไหม?" เกิดขึ้นเมื่อ Request ใช้ Method `PUT`/`DELETE`/`PATCH` หรือมี Header พิเศษเช่น `Authorization` หรือ `Content-Type: application/json` ถ้า Server ไม่ตอบ Preflight ด้วย Header ที่ถูกต้อง Browser จะไม่ส่ง Request จริง

**คำถาม 2:** ทำไม `origin: '*'` ถึงใช้คู่กับ `credentials: true` ไม่ได้?

**แนวคำตอบ:** เพราะ `credentials: true` หมายถึง Browser จะส่ง Cookies และ Authorization headers ไปด้วย ซึ่งเป็นข้อมูลสำคัญ การอนุญาต `*` (ทุก Origin) พร้อมกับส่ง credentials เท่ากับเปิดช่องให้เว็บอันตรายใดๆ เรียก API แทน User ได้ ซึ่งเป็นความเสี่ยงด้าน Security สูงมาก Browser จึงบล็อกการรวมกันนี้ไว้โดยเด็ดขาด

**คำถาม 3:** ทำไม `app.use(cors())` ต้องวางก่อน Routes ทุกตัว?

**แนวคำตอบ:** Express ประมวลผล Middleware ตามลำดับที่ลงทะเบียน ถ้า `cors()` อยู่หลัง Routes เมื่อ Browser ส่ง Preflight (`OPTIONS`) มา Express จะหา Route handler ก่อน ถ้าไม่เจอ Route ที่รับ OPTIONS จะส่ง 404 กลับไปทันทีโดยไม่มี CORS Headers — ทำให้ทุก Request จาก Frontend ถูกบล็อกหมด

:::

## 📚 Quick Reference

```javascript
// Minimal setup (Dev)
app.use(cors());

// WSA2026 Production Setup
app.use(cors({
    origin: process.env.CLIENT_URL,
    methods: ['GET', 'POST', 'PUT', 'DELETE', 'PATCH'],
    allowedHeaders: ['Content-Type', 'Authorization'],
    credentials: true,
    maxAge: 86400
}));
```

| สิ่งที่ต้องการ | Option |
|:---|:---|
| อนุญาตทุก Origin | `origin: '*'` |
| ระบุ Origin เดียว | `origin: 'https://...'` |
| หลาย Origin | `origin: ['https://a.com', 'https://b.com']` |
| Dynamic check | `origin: (origin, cb) => cb(null, true)` |
| อนุญาต JWT/Cookie | `credentials: true` (ต้องคู่กับ origin ชัดเจน) |
